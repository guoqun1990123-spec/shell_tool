### Task 3：修复 `_title_overridden` 语义偏差（Bug #2）

**问题：** `df_to_card_state` 中 `_title_overridden = bool(str(card.get("Section title", "")).strip())`——只要 Section title 非空就标为 override，导致从 Excel/YAML 加载时所有行都失去 Section no → Section title 的自动联动。

**Files:**
- Modify: `web/config_editor.py`，`df_to_card_state()` 函数（约第 57-71 行）

**Step 1: 理解正确语义**

`_title_overridden=True` 的含义应该是「用户在 Web UI 里手动修改过 Section title，不再跟随 section_map 自动填充」。从文件加载时，即使 Section title 有值，也应视为「尚未被用户覆盖」，允许 Section no 变动时重新自动填充。

**Step 2: 修改 `df_to_card_state`，加载时一律将 `_title_overridden` 设为 False**

```python
def df_to_card_state(df: pd.DataFrame) -> list[dict]:
    if df is None or df.empty:
        return []
    rows: list[dict] = []
    for _, row in df.iterrows():
        card: dict = {}
        for col in CONFIG_COLS:
            val = row.get(col, "")
            card[col] = "" if (val is None or (isinstance(val, float) and pd.isna(val))) else val
        card["_id"] = str(uuid.uuid4())
        card["_level"] = "collapsed"
        card["_title_overridden"] = False   # 加载时不视为用户手动覆盖
        card["_tableno_overridden"] = False
        rows.append(card)
    return rows
```

### Task 8：修复 pop 含自定义值时被丢弃（Bug #8）

**问题：** `_render_level1` 的 multiselect default 只含 `all_pop = pop_options + cur_pop_list`，若 `cur_pop_list` 中的值因为空格差异不在 `all_pop` 中，会被 `[p for p in cur_pop_list if p in all_pop]` 过滤掉，导致切换卡片后 pop 值静默丢失。实际上 `all_pop` 已经包含了 `cur_pop_list`，问题在于 `default` 过滤逻辑多余——`all_pop` 本身就包含 `cur_pop_list` 的所有值，所以 `default` 可以直接用 `cur_pop_list`。

**Files:**
- Modify: `web/config_editor.py`，`_render_level1()` 中 pop multiselect（约第 458-471 行）

**Step 1: 当前代码**

```python
cur_pop = str(card.get("pop", "") or "")
cur_pop_list = [p.strip() for p in cur_pop.split(",") if p.strip()]
all_pop = list(dict.fromkeys(pop_options + cur_pop_list))

    "pop", options=all_pop,
    default=[p for p in cur_pop_list if p in all_pop],
    ...

```

**Step 2: `default` 直接用 `cur_pop_list`，`options` 已包含所有可能值**

Streamlit multiselect 要求 default 中的每个值都必须在 options 中，而 `all_pop = dict.fromkeys(pop_options + cur_pop_list)` 已经保证 `cur_pop_list` 中的值都在 `all_pop` 里，所以 default 过滤是不必要且有害的：

```python

    "pop", options=all_pop,

)
new_pop = ", ".join(new_pop_list)
if new_pop != cur_pop:
    st.session_state[_CARD_STATE_KEY] = _update_card(
        card_state, card_id, pop=new_pop
    )
    st.rerun()
```

### Task 12：YAML 预览折叠时跳过序列化（Bug #11）

**问题：** 底部「YAML 预览」expander 折叠时，每次 `st.rerun()` 都执行 `dump_yaml()`，大型配置产生不必要计算。

**Files:**
- Modify: `web/app.py`，底部 YAML 预览 expander（约第 812-821 行）

**Step 1: 当前代码**

```python
with st.expander("YAML 预览"):
    try:
        preview = dump_yaml(
            edited_config,
            st.session_state.datasets,
            st.session_state.protocol_name,
        )
        st.code(preview, language="yaml")
    except Exception as e:
        st.error(f"序列化失败：{e}")
```

**Step 2: 用 `expanded=False` + 按钮触发懒计算**

Streamlit expander 折叠时内部代码仍然执行，真正的懒计算需要用按钮控制。将 YAML 预览改为按钮触发：

```python
_yaml_preview_key = "_yaml_preview_content"
with st.expander("YAML 预览", expanded=False):
    if st.button("生成 YAML 预览", key="btn_yaml_preview"):
        try:
            st.session_state[_yaml_preview_key] = dump_yaml(
                edited_config,
                st.session_state.datasets,
                st.session_state.protocol_name,
            )
        except Exception as e:
            st.session_state[_yaml_preview_key] = f"序列化失败：{e}"
    content = st.session_state.get(_yaml_preview_key, "")
    if content:
        st.code(content, language="yaml")
```

**Step 3: 验证**

1. 正常编辑 Config，页面响应速度无变化
2. 打开「YAML 预览」expander，点「生成 YAML 预览」按钮后显示 YAML 内容
3. 再次修改 Config 字段，YAML 预览不自动刷新（需重新点按钮），属于预期行为

**Step 4: Commit**

```bash
git add web/app.py
git commit -m "perf: YAML 预览改为按钮触发，避免每次 rerun 序列化"
```
